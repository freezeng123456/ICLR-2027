# 第一部分：背景、基线、在做什么问题

## 1. PFN 是什么

PFN = **Prior-data Fitted Network**，先验数据拟合网络。

传统做法是：拿到数据集 → 训练一个模型 → 预测。
PFN 的做法是：**完全不训练**。你把整个训练集当作"上下文"塞进一个 transformer 的输入，
一次前向传播直接输出测试点的预测。形式上就是给 LLM 喂 few-shot prompt，只不过这里的
"例子"是表格的行。

它怎么获得这个能力？靠**预训练**：

1. 作者先定义一个**先验 P**——一个生成合成任务的分布。比如"从高斯过程里采函数"，
   或者表格 PFN 用结构因果模型（SCM）随机生成表格任务。
2. 从 P 里采几百万个合成任务，每个任务给模型看一部分数据、让它预测剩下的。
3. 训练目标就是最小化预测的负对数似然。

**关键的理论事实**（Müller et al. 2022 的原始论文）：这个训练目标的最优解，
**恰好是先验 P 下的贝叶斯后验预测分布**。所以训练好的 PFN 本质上是
"在先验 P 下做贝叶斯推断"的一个**摊销近似**（amortized approximation）——
把本来要现算的贝叶斯积分，预先压进网络权重里。

TabPFN、TabICL 就是把这套用在表格数据上。2025–2026 年它们已经在 TabArena、TALENT
这些基准上超过了调参的 CatBoost / XGBoost，是表格领域现在的 SOTA。

## 2. 问题从哪来：先验是别人替你选的

这里有件所有人都知道、但没人认真处理的事：

> **先验 P 是模型作者在预训练时定死的。你作为使用者既选不了，也看不见。**

那么，如果你的数据不符合 P，会发生什么？

直觉答案是"性能会变差"。但**具体怎么变差、变差在哪个维度、能不能提前发现、能不能补救**
——这些都没人系统研究过。

这就是这个项目的问题：**PFN 的先验错配（prior misspecification）到底表现为什么？**

## 3. "基线"这个词在这里有两个意思

### (a) 领域现状 —— 这才是项目真正要挑战的东西

现在整个表格 PFN 领域的评测方式是固定的：在 TabArena（51 个数据集）/ TALENT（300 个）
上比**准确率或 ROC AUC**，对手是 CatBoost、XGBoost、LightGBM、AutoGluon，
以及其他 PFN（TabPFN-2.5/2.6、TabICLv2、TabDPT）。所有排行榜、所有论文，一个口径。

**这个项目的核心主张就是：这个口径系统性地漏掉了一整类失效。**

这一点很重要，因为它决定了这篇论文**不跟任何人比准确率**——那是一条已经挤满人、
而且需要大算力的死路。

### (b) 实验里的对照参照 —— 见 [08-PFN基线盘点.md](08-PFN基线盘点.md)

简要重述：GP 线用四个解析参照（P 下的混合后验 / 真实参数的后验 / 固定参数的后验 /
全预测 0）；表格线一律以"不加 anchor"为基准，另配随机标签 anchor（扣掉"多了 60 行"的
副作用）和额外真实数据（增益上界）。统计一律同种子配对。

## 4. 五轮实验走到了哪

按顺序，每一步都是上一步逼出来的：

**第一步，受控设定下机制成立。** 自己训一个小 GP PFN（因为高斯过程有解析解，
可以逐点核对答案）。往上下文里塞**远处**的 anchor 样本——远到对查询点的函数值不含任何
信息，任何近邻检索都会把它们丢掉。结果模型的预测朝解析贝叶斯预测的方向移动，
斜率 0.89 / 0.95。**所以起作用的是"先验被掰动"，不是"多了近邻"。**

**第二步，搬到真实表格 PFN（TabICLv2），在"平滑度"轴上撞墙。** 构造的结构化 anchor
和随机标签 anchor 带来的增益一样多（净差 t = 0.6 和 1.4，完全不显著）。那 1.5 个百分点
跟 anchor 里装了什么无关，纯粹是"多了 60 行远处数据"的副作用。**这个坑是事先埋的随机
标签对照抓出来的**——没有这个对照就会误报成功。

**第三步，诊断失败原因，结果推翻了自己的猜测。** 原猜测是"远处的行根本没被读"。
于是把**确实含目标任务信息**的 anchor 放到不同距离测衰减。结果平移 6 个单位后净增益
仍有 +0.023 / +0.046（t = 3.1 / 6.3）——**远处的行是被用的**。所以问题不在距离，在轴。

**第四步，换成噪声轴，成了。** 远置的、与目标任务毫无关系的 anchor，只改它自己的标签
噪声率：

| anchor 噪声 | 0% | 10% | 25% | 40% | 50% |
|---|---:|---:|---:|---:|---:|
| 置信度（规则型目标） | 0.780 | 0.763 | 0.738 | 0.730 | 0.727 |
| 置信度（平滑型目标） | 0.762 | 0.742 | 0.716 | 0.701 | 0.700 |
| 准确率变化 | +0.014 | +0.015 | +0.012 | +0.015 | +0.014 |

严格单调，两个任务都是，t = −7.1 / −8.5。**而准确率基本不动。**
模型从一批与目标任务无关的远处数据里推断出一个全局噪声水平，然后把它用到了目标任务上。

**第五步，这个杠杆能反过来用。** 目标任务噪声 30% 时，把 anchor 噪声从 0% 提到 50%：
log loss 0.7683 → 0.7228，ECE 0.1395 → 0.1002（不加 anchor 是 0.2023，**等于校准误差
减半**）。而目标任务只有 3% 噪声时增量只有 0.006。**收益精确集中在模型本就过度自信的
场合。**

**第六步（后续），搞清楚了为什么噪声轴通、平滑度轴不通——而且答案不是原来猜的那个。**

原假说是"先验里显式存在的隐变量才掰得动"。为验证，训了三个先验不同的 PFN：
A 只有长度尺度变、B 只有噪声变、C 都变。**假说被自己的实验打掉了**——A 的先验里噪声是
固定的，按假说该毫无反应，结果它在噪声掰动上的相关系数 +0.899，全表最高。

真相是**错误归因**：A 没有"噪声"这个概念，于是把"anchor 变吵了"用它仅有的隐变量重新
解释了一遍——吵的观测看起来像波动剧烈的函数，所以它把长度尺度往小推。而在 A 自己的
先验下，精确贝叶斯做的**正是同一件事**。

签名实验直接证实了这条：同一个操纵在不同先验的模型上留下不同痕迹。A 在噪声操纵下
**连预测均值都被带动**（相关 +0.802，这是"经长度尺度绕道"的签名）；B 在尺度操纵下
**标准差被带动**（相关 +0.931，"经噪声绕道"的签名）。而每个格子里 PFN 都跟住了
**它自己先验下**的解析参照。

> **模型在自己的先验下永远是忠实的贝叶斯推断者。缺少某个隐变量不会让它沉默，
> 而是让它把你的数据用手头仅有的隐变量重新解释一遍。错的不是它的推断，是它的世界观。**

**第七步，解释表格 PFN 为什么跟得差。** 先验最丰富的 C 反而最差（相关只有 0.52–0.64）。
排掉了"组合多所以每种见得少"这个混淆——A144 用完全相同的 144 种组合、相同步数，
仍有 +0.924 / +0.893；而且 144 个尺度的单隐变量模型比 12 个尺度的还好。真正原因是
**两个隐变量互相纠缠**："平滑但吵"和"波动但干净"产生几乎一样的观测，摊销网络要解一个
部分不可辨识的问题，逼近精确贝叶斯的能力就掉下来了。

**这就把整条线接上了**：真实表格 PFN 的先验隐变量极多且高度纠缠，所以它偏离精确贝叶斯
很远，只有在相对可辨识的轴上（噪声）才测得到掰动；平滑度那种和一堆因素缠在一起的轴上，
掰动被稀释到测不出来。**这不是模型的缺陷，是摊销推断在纠缠先验下的必然结果。**

# 第二部分：方法与指标

## 1. 方法

**往上下文里追加"远置 anchor 行"，通过控制它们的标签噪声水平，调节模型在目标任务上的
置信度。**

具体构造：

- anchor 的特征整体平移 6 个单位（8 维全平移），确保在特征空间里离测试点极远
- anchor 的标签来自与目标任务**完全无关**的另一个函数，因此**不含任何关于答案的信息**
- 唯一被操纵的量是 anchor 自己的标签噪声率 η
- 模型从整个上下文推断一个全局噪声水平，这个推断被应用到目标任务的预测上

**为什么这算"方法"而不只是"漏洞"**：因为它可控、有方向、且收益可预测。
目标任务噪声大 → 模型过度自信 → 用高噪声 anchor 压下来；目标任务干净 → 用低噪声
anchor 让它保持锐利。

**同一个机制的两面**：
- 当成漏洞看——上下文里任何位置的无关数据，都会悄悄把模型在别的查询上的置信度带偏
- 当成方法看——可以拿它做免训练的校准

## 2. 指标

这是整个项目最关键的一点，也是它跟其他 PFN 工作最本质的区别：

| 指标 | 角色 | 期望 |
|---|---|---|
| **log loss** | **主指标**，严格适当评分规则，同时反映准确与校准 | 降低 |
| **ECE**（期望校准误差） | 辅指标，纯校准 | 降低 |
| **准确率** | 对照指标，纯决策 | **保持不变** |

注意最后一行。**在别的论文里"准确率不动"是失败；在这里它是论点的一部分。**
它证明这个效应发生在校准维度上，而这恰好解释了为什么一个只看准确率的领域至今没发现。

已有的数字：

- ECE：0.2023（不加 anchor）→ 0.1002（50% 噪声 anchor），**减半**
- log loss：0.7683 → 0.7228
- 准确率：+0.014 → +0.014，**基本不动**

## 3. 论文的一句话

> **PFN 是一个在你没选择的先验下做忠实贝叶斯推断的模型；数据违背那个先验时它不会报错，
> 而是悄悄地把你的数据换个说法解释掉，代价记在校准上而不是准确率上——所以整个只看
> 准确率的评测体系至今没发现。**

四块齐了：**理论**（错误归因；纠缠先验导致摊销逼近变差）、**诊断**（错配表现为校准失真
而非准确率下降）、**方法**（用 anchor 噪声做免训练校准）、**以及"为什么以前没人发现"**。

# 第三部分：这个定位好在哪，以及最大的风险

## 好在哪（有数据支撑）

见 [07-oral清单与趋势.md](07-oral清单与趋势.md)：ICLR 2026 里放大倍数最高的主题是
"优化器与训练方法"（1.37×），而摊开那 33 篇标题看，构成是四类——**"标准做法其实是错的"、
"把大家天天用的东西的数学做对"、"证伪一个方法的理论根基"、"给经验规律一个可外推的刻画"**。
这个 PFN 项目同时命中第一类和第四类。

反过来，**评测（0.93×）、效率（0.94×）、多模态（0.83×）这些"比性能"的大池子全在 1.0
以下**。所以"不跟 TabICLv2 拼准确率"这个决定，从数据上看是对的。

## 最大的风险：温度缩放

这一条在 [08](08-PFN基线盘点.md) 里已经提过，但**论文定位转到校准之后，它从"应该补"
升级成"不补就没法投"**。

论文的方法半边现在是"我们能改善校准"。任何人看到这句话，第一个问题必然是：

> **那我直接做温度缩放不就行了？**

温度缩放是一个参数、一行代码、在保留集上拟合，是校准领域三十年的默认基线。
还有一个更近的变体：**往自己真实的上下文里注入同等噪声**，而不是加远处 anchor。

如果这两个之中任何一个在 log loss / ECE 上打平你的 anchor 方案，方法半边就没了——
论文退回到"一个有趣的机制现象"，那是完全不同（且弱得多）的一篇。

**必须主动做、主动写**，即使输了。输了也有话说：anchor 方案不需要保留集、不需要额外
拟合、且揭示的是模型内部的推断机制——但这个论证只有在你自己先摆出对比时才成立。

## 其余待办（按重要性）

1. **温度缩放 + 上下文注噪的对照** —— 决定方法半边成不成立
2. **搬到真实数据集**（TabArena / TALENT 挑 10–15 个）—— 合成数据撑不起一篇论文
3. **在 TabPFN-2.5 上复现** —— 决定标题能写 "PFNs" 还是只能写 "TabICL"
4. **TabPFN-kNN 检索基线**（LoCalPFN 的公开代码里现成）—— 把"远处 anchor 不是近邻效应"
   从论证升级成演示

第 1、3、4 条都是纯推理，2 张 H20 够用。第 2 条需要下载数据集，也在能力范围内。

## 两处作者已自行标注的弱点（保留，别忘了）

  但低噪声那一侧的曲线在 15% 之后基本持平，谈不上有明确最优点。**这条不要写进论文。**
