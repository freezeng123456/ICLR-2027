# 换到 logits：为什么，以及具体做什么

这份文档取代 [05](05-理论方向.md) 第四节的 agent 提案。理由先说清楚，然后给方案。

---

## 一、先算清楚 agent 那条线为什么该放弃

你的直觉是对的，但真正致命的不是 token 数，把两笔账都摆出来：

**要拟合什么。** 要把两参数模型（脱轨率 ε、恢复率 ρ）和单参数的独立模型区分开，
每个实验格子里的成功率置信区间得足够窄。成功率在 0.3 附近、要做到 ±0.05 的 95% CI，
每格约需 320 个 episode。格子数 = 6 个时程 × 4 个难度 × 3 种恢复条件 × 2 个模型 = 144，
**合计约 46,000 个 episode**。

**token 账其实还行。** 每个 episode 约 3 万 token，合计 14 亿 token。用 Qwen3-30B-A3B
按实测打折后约 10,000 tok/s 算，纯生成约 **39 小时**。这个数字本身不吓人。

**真正的杀手是工程。** 三条叠加：

- episode 内部是**串行**的，每一步都要等环境返回，batch 只能靠横向并发几百个 episode 来
  填。harness 一旦有 bug，几万个 episode 的日志就废了。
- 你需要**逐步记录状态**——每一步是否脱轨、是否恢复、错误可否撤销。这不是现成 harness
  能给的，得自己写判定逻辑，而判定逻辑本身就是研究内容的一部分（判错了理论就拟错）。
- 环境延迟和失败重跑通常让实际墙钟是纯生成时间的 3–5 倍，**即 120–200 小时**。

所以现实是：**头两三周全部耗在写 harness 上，第五周才知道理论拟不拟得动。** 7 周排期里
这是不能承受的风险结构。你的判断没错。

**对照 logits 方案的成本。** 数据采集就是一个 for 循环调 `model(...).logits`，加一个
随机化 SVD。**GPU 时间以小时计，代码以天计**，而且第一天就能拿到数据开始推公式。
两者不在一个量级上。

## 二、有个刚拿了 ICLR Oral 的口子，正好空着

《Sequences of Logits Reveal the Low Rank Structure of Language Models》
（Golowich, Liu, Shetty，ICLR 2026 **Oral**，[arXiv:2510.24966](https://arxiv.org/abs/2510.24966)）
做了三件事：

1. **测量**：由 logits 构成的"扩展 logit 矩阵"（对不同 history × future 组合）具有低近似
   秩，奇异值按幂律衰减 σ_i ≈ C·i^(−α)。
2. **一个惊人的经验规律**：**α 在不同模型家族和规模上高度一致，都略高于 0.5** ——
   OLMo-7b 0.536、OLMo-1b 0.561、Gemma-1b 0.565、Llama-1b 0.573、Mamba-1.4b 0.563。
   注意 Mamba 也在里面，**连架构都换了，指数还是那个值**。
3. **理论**：低 logit 秩等价于可表示为时变的 Input Switched Affine Network，给出表达能力
   与可学习性保证；并用它做了 LINGEN（用无关 prompt 的输出线性组合来生成目标续写）。

他们还观察到：**低秩结构在初始化时不存在，在预训练早期涌现，并随训练演化。**

### 他们没做的两件事，都是好题

**空缺一：为什么 α ≈ 0.55，而且跨架构普适？**
一个在 Transformer 和 Mamba 上都成立、跨两个数量级规模都成立的普适指数，是**在喊着要一个
解释**。而这类问题有成熟的理论工具——数据协方差的幂律谱驱动神经网络 scaling law，
这条线（随机矩阵理论那一支）已经有完整机器可用。**把 logit 谱的指数和数据谱的指数、
进而和 scaling law 联系起来，会是一个很强的结果。** 高风险高回报。

**空缺二（我建议做这个）：后训练对这个谱做了什么？**
他们只看了**预训练**checkpoint。而所有人都知道 RL 后训练会让熵坍缩、多样性下降——
**但没人从秩的角度看过。** 这个空缺又大又干净，而且成本极低。

## 三、具体提案：把 logit 谱当作观察后训练的透镜

### 主张的骨架

1. **测量**：同一模型家族的 base / SFT / RLHF / RLVR 各阶段，logit 谱怎么变。
   假设是 **奖励最大化会压缩谱、降低有效秩**——因为策略在集中。
2. **理论**：证明带 KL 正则的奖励最大化会以可刻画的方式收缩 logit 谱，给出
   **KL 预算与秩下降之间的定量关系**。这一步是可做的：KL 约束下的最优策略是
   base 策略的指数倾斜，倾斜对谱的作用可以算。
3. **预测**：秩的下降应当能**定量预测** best-of-N / self-consistency 收益的衰减。
   也就是说，**test-time scaling 里那个"众数天花板"，是后训练秩坍缩的后果。**

第 3 条是这个提案真正值钱的地方：它把一个刚得 Oral 的量（logit 秩）、一个人尽皆知但没有
机制解释的现象（RL 后多样性坍缩）、和一整片热门文献（test-time scaling）用**一个可测量的
标量**串起来了。

### 三条可证伪的预测

- **P1**：有效秩沿 base → SFT → RLHF/RLVR 单调下降，且下降幅度随 KL 预算（或训练步数）
  单调。
- **P2**：秩下降主要发生在**谱的尾部**（小奇异值方向），对应低概率 token 的表达能力
  ——这可以直接解释为什么 RL 后的模型在需要多样性的任务上崩得更厉害，而在贪心解码上
  反而更好。
- **P3**：跨模型比较时，**有效秩应当比熵更好地预测 best-of-N 的增益上限**。熵是一阶量，
  秩是分布族的维度；如果 P3 成立，说明该看的量一直找错了。

P3 如果成立，是个很有冲击力的结论，而且检验成本极低。

### 为什么这个可做

**数据几乎免费。** 构造扩展 logit 矩阵只需要前向传播：几千个 prompt × 每个约 500 token，
每模型约 100 万 token 的 prefill。用 Qwen3-30B-A3B 算，2×3e9×1e6 ≈ 6e15 FLOPs，
在 H20 上**几分钟**。十个 checkpoint 也就一小时以内。

**checkpoint 都是现成的。** 需要同家族的各训练阶段，这些都公开：
Qwen3 的 base / instruct / thinking、OLMo 的完整 checkpoint 序列（含后训练各阶段）、
Llama 的 base / instruct、Tulu 系列。**不用自己训练任何东西**——这正好绕开 H20 最弱的
算力短板。

**唯一的工程点是存储。** |V|≈150k 的 fp16 logits，每个位置 300 KB；10 万个位置就是 30 GB。
解决办法是**流式随机化 SVD**（不落盘存全矩阵）或对词表做子采样。这是个标准技术问题，
不是研究风险。

**理论工具是成熟的。** KL 正则下的最优策略有闭式（指数倾斜），倾斜对矩阵谱的作用可以用
扰动分析处理。不需要造新机器。

### 和那篇 Oral 的区别必须写清楚

他们做的是**预训练阶段的测量 + 表达能力抽象 + 一个生成应用**。你做的是**后训练对谱的
作用 + 一个可证伪的下游预测**。引言第二段必须把这个区别讲明白，否则审稿人第一反应就是
"这不是 Golowich et al. 吗"。

反过来，**建立在一篇刚拿 Oral 的工作上是优势不是劣势**：审稿人认得这个对象，你不用花
篇幅论证它为什么重要，而且社区刚刚给它盖过章。

## 四、备选：解释 α 为什么普适

如果团队理论功底强，空缺一（为什么 α ≈ 0.55 且跨架构普适）的天花板更高——它是在解释一个
普适常数，而且能接到 scaling law 那条线上。

**但风险也高得多**：可能推半天发现只能得到"存在某个幂律"这种平凡结论。建议作为
第二篇或者主线做出来之后的延伸，不要在 7 周里当主攻。

如果想做，起点是数据协方差幂律谱驱动 scaling law 的那批工作（Maloney–Roberts–Sully、
Bahri 等），核心问题是：**logit 谱的指数和数据潜在谱的指数之间是什么关系？**
如果能证明 α = f(数据谱指数)，且 f 与架构无关，就解释了普适性。
