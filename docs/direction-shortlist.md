# ICLR 2027 方向候选与选型建议

> 状态：待你拍板。写于 2026-08-17，距摘要截止 32 天、正文截止 39 天。
> 本文中提到的论文与结论来自一次文献扫描，**引用前必须逐条核对原文**（ICLR 2027 把编造引用列为 desk reject 事由）。

## 0. 先认清约束

剩余时间只够做**一个**方向，而且这个方向必须满足：主实验能在 2 周内跑完、用 ≤8B 的开源模型就能证明、失败了也还有话说。
这直接排除了一大类选题（见 §4）。

同时要认清今年的评审环境：ICLR 2026 收到 19,525 篇投稿、录用率 27.4%，且约 21% 的评审是 AI 生成的。
结论很直接：**论文必须在 60 秒内被一个疲惫的评审读懂**。一句话的核心 claim + 一张主图定生死，堆工作量没有用。

## 1. 推荐方向 A：记忆系统何时反而有害，以及一个有原则的写入准入策略

**这是我的首选建议。**

### 机会在哪

2026 年已经有一批受控实验确立了一个让整个方向难堪的负面结果：在 **token/预算对齐（budget-matched）** 的条件下，
专门设计的 agent memory 系统常常打不过"把最近历史直接塞进 context"这种朴素基线，长时程下甚至跌破 no-memory 基线。
证据分散在多项独立工作里（WebArena 上 token-matched 的 online memory/skill/workflow 模块不敌 vanilla baseline；
lifelog 长程上有损的复杂记忆系统不敌高保真 RAG；医疗域的 memory saturation；机器人域 distractor session 导致的检索衰减）。

关键判断：**诊断已经被别人做完了，但没有人给出有原则的正面解法。** 多篇综述把 learned forgetting、
continual consolidation、causally grounded retrieval 明确列为未解开放问题。这是一个已经被验证存在、
但解法空白的缝隙——对时间紧张的人来说这是最好的位置，因为你不用再花两周去论证"这个问题存在"。

### 核心 claim（一句话）

记忆系统的净收益由一个**可以在写入时刻事先估计**的量决定：该条目的期望未来复用价值，减去它对检索邻域造成的污染代价。
把 memory 的 write 决策形式化成**准入控制（admission control）**问题，就能解释已有的负面结果，并把交叉点推后甚至消除。

之所以说它有力，是因为它给出了机制解释：memory 掉到 baseline 之下不是因为"检索不够准"，
而是因为低复用、高噪声的条目在持续污染检索邻域——写入越多越糟，这正好解释了为什么退化随交互轮数单调加剧。

### 主图长什么样

x 轴是交互轮数（或 token 预算），y 轴是任务准确率。三条线：
朴素 memory 系统（先升后降，与 no-memory 基线交叉）、no-memory / recent-history 基线（平）、
加了准入控制的 memory（不交叉）。**这张图就是论文。**

### 实验计划

- **数据/环境**：多 session 的用 LoCoMo、LongMemEval、MemoryAgentBench、MemoryArena；agentic 长时程的用 WebArena 或类似任务流。至少覆盖 2 个性质不同的环境。
- **基线（必须预算对齐）**：no-memory、recent-history in-context、vanilla RAG、一个主流 memory 框架（Mem0 / MemGPT 类）。预算不对齐的比较会被评审直接抓住。
- **关键实验三件套**：
  1. 预算对齐曲线，展示交叉点确实存在（复现他人结论，成本低，作为地基）。
  2. 污染注入：人为注入 stale / 矛盾 / 错误条目，测退化速率对污染比例的敏感性。
  3. 你的准入策略把交叉点推后或消除。
- **最有说服力的一个消融**：用"未来真实复用次数"构造 oracle 准入上界。
  如果 oracle 上界远高于朴素 memory，就证明了这个问题**可学**；再证明你的可估计代理逼近 oracle。
  这个实验很便宜，但它把论文从"又一个 trick"抬升到"揭示了一个可学习的结构"。

### 成本与风险

方法本身可以很轻——准入打分器甚至可以是 logistic regression 或一个小模型，主要开销是推理。
风险是撞车：综述刚出，说明盯着这个方向的人不少。缓解办法是**不要做成又一个 memory 框架**，
把 claim 死死钉在"可预测的准入判据 + oracle 上界"上，框架化的东西一律放附录。

### 你的独有优势

腾讯的长时程、多 session 真实用户交互 trace 是学术界拿不到的。方向 A 恰好吃这口数据：
一个真实产品上的预算对齐曲线，比任何公开 benchmark 都更有说服力。注意数据合规与匿名化，
并准备好用公开 benchmark 复现同一结论（评审无法验证内部数据）。

## 2. 备选方向 B：多验证器组合与奖励攻击

### 机会在哪

RLVR 一旦离开数学和代码就卡在没有 verifier 上。工业界的实际做法是拼若干个"部分验证器"（内容、风格、合规），
但**如何组合它们没有任何有原则的框架**——加权平均？取最小？连乘？公开讨论里明确写着这一块 unexplored。

### 核心 claim

组合规则本身决定了奖励攻击的表面。每个部分验证器都有自己的误判区域，策略最终会被推向**所有验证器盲区的交集**。
不同组合算子（min / 乘积 / 加权和 / soft-min）诱导出的盲区交集几何不同，由此可以推导出可利用性的上界，
并给出一个抗攻击的组合算子。

### 为什么值得考虑

理论与小规模实验都能做，不需要大模型；而且结论工业界立刻能用，引用会很好看。
实验用 1.5B 级模型 + 合成任务 + 真实开放式任务（摘要、指令跟随），故意构造弱验证器，
测不同组合算子下的 reward hacking 速度与真实质量的背离。

### 风险

要跑 RL，比 A 贵；需要一点理论功底才能把界写对。如果你手上 RL 训练 pipeline 是现成的，B 的性价比会反超 A。

## 3. 高风险高回报方向 C：RLVR 的 task-advantage ratio 能否测量与控制

近期理论工作定义了 task-advantage ratio，用它刻画 RLVR 能否学到正确的中间步骤，
并把"能否在真实 LLM 上测量它、能否从 base model 预测它、能否通过训练设计控制它"明确列为关键开放方向。
谁先给出可用的估计器 + 一个基于它的干预（重排课程或改采样），谁就拿下一篇很强的论文。

**但不建议现在选它。** 这是最挤、最贵、最吃理论功底的方向，5 周内做砸的概率很高。
把它记在待办里，作为下一个周期（NeurIPS / ICML）的目标。

## 4. 明确不要做的事

- **又一个 benchmark。** ICLR 2026 光是 Benchmark 关键词就有 335 篇，评审已经疲劳。除非你的 benchmark 能**推翻**领域现有共识，否则不做。
- **又一个 agent framework / 又一个 DPO 变体。** 没有机制解释的增量方法今年基本活不下来。
- **需要预训练或大规模训练才能证明的 claim。** 时间不够，而且你和大厂正面拼算力没有优势。
- **追 3 个月内刚火起来的方向**（例如 dLLM 的 test-time scaling）。5 周内做不出差异化，而且 2026 年 8 月刚出了该方向的系统性评测综述，很容易被 scoop。

## 5. 选型判据（拍板前逐条打勾）

1. 核心 claim 能不能用一句话说清，并且这句话让人**意外**？
2. 主实验能不能在 2 周内跑完，且只用 ≤8B 的开源模型？
3. 如果结果是负的，论文还成立吗？（好方向的特征：negative result 本身也是贡献）
4. 有没有一个 oracle 或上界实验，能证明"这个问题可学"？
5. 所有基线能不能在**同一预算**下公平比较？

方向 A 五条全过，B 过 4 条（第 2 条取决于你的 RL pipeline），C 只过第 1 和第 3 条。

## 7. 现在就要确认的两件事（与研究无关，但能直接毙掉投稿）

1. **合作者名单与评审资格。** 如果你和全部合作者都没有主流 ML 会议/期刊的已接收论文，今年只能投 1 篇；
   并且每篇投稿**必须**至少有一位作者注册评审至少 3 篇，否则 desk reject。资格以摘要截止日已接收的论文为准。
   摘要截止后不能再加作者——所以名单要在 9/18 前定死。
2. **AI 使用披露。** 今年新增强制章节（不计页数）。用 AI 生成合成数据、形成数学命题、协助证明、
   设计方法或实验、实现方法、解释结果，都属于必须披露的范围。提前写好，别在截止前一晚补。
